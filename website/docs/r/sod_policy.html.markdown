# identitynow_sod_policy

Manages a separation of duties (SOD) policy. A policy is either a `GENERAL` policy, defined by a search query, or a `CONFLICTING_ACCESS_BASED` policy, defined by two sets of entitlements that one identity must not have together. The query of a conflicting access based policy is generated by IdentityNow.

## Example Usage

### Conflicting access based policy

```hcl
resource "identitynow_sod_policy" "payables_receivables" {
  name                  = "Payables vs Receivables"
  description           = "Nobody may both create and approve payments."
  type                  = "CONFLICTING_ACCESS_BASED"
  state                 = "ENFORCED"
  compensating_controls = "Monthly payment review"
  correction_advice     = "Remove one of the conflicting entitlements."
  tags                  = ["SOX"]

  owner_ref {
    id   = "2c91808568c529c60168cca6f90c1313"
    type = "IDENTITY"
  }

  violation_owner_assignment_config {
    assignment_rule = "STATIC"

    owner_ref {
      id   = "2c9180867624cbd7017642d8c8c81f67"
      type = "GOVERNANCE_GROUP"
    }
  }

  conflicting_access_criteria_json = jsonencode({
    leftCriteria = {
      name = "Payables"
      criteriaList = [
        { type = "ENTITLEMENT", id = "2c9180866166b5b0016167c32ef31a66" }
      ]
    }
    rightCriteria = {
      name = "Receivables"
      criteriaList = [
        { type = "ENTITLEMENT", id = "2c9180866166b5b0016167c32ef31a67" }
      ]
    }
  })
}
```

### General policy

```hcl
resource "identitynow_sod_policy" "admins" {
  name         = "Privileged administrators"
  policy_query = "@access(name:\"Domain Admins\") AND @access(name:\"Security Auditors\")"

  owner_ref {
    id   = "2c91808568c529c60168cca6f90c1313"
    type = "IDENTITY"
  }
}
```

## Arguments Reference

The following arguments are supported:

* `name` - (Required) Policy business name.
* `owner_ref` - (Required) Owner of the policy. Exactly one block is required. Contains:
  * `id` - (Required) Owner ID.
  * `type` - (Required) Owner type, `IDENTITY` or `GOVERNANCE_GROUP`.
  * `name` - (Optional) Owner name. When omitted, the name resolved by the API is not tracked.
* `type` - (Optional) Policy type, `GENERAL` (default) or `CONFLICTING_ACCESS_BASED`. Changing this forces a new policy to be created.
* `policy_query` - (Optional) Search query of the policy. Required for `GENERAL` policies. For `CONFLICTING_ACCESS_BASED` policies the query is generated by the API from `conflicting_access_criteria_json` and must not be set; it is exported as an attribute.
* `conflicting_access_criteria_json` - (Optional) Conflicting access criteria as a JSON object with `leftCriteria` and `rightCriteria`, each with a `name` and a `criteriaList` of 1 to 50 entitlement references (`type = "ENTITLEMENT"` and `id`). Required for `CONFLICTING_ACCESS_BASED` policies and not allowed for `GENERAL` policies. Use `jsonencode()`.
* `description` - (Optional) Policy description.
* `external_policy_reference` - (Optional) Reference to an external policy.
* `compensating_controls` - (Optional) Compensating (mitigating) controls.
* `correction_advice` - (Optional) Advice on how to correct a violation.
* `state` - (Optional) Whether the policy is enforced, `ENFORCED` or `NOT_ENFORCED`. When not set, the value chosen by IdentityNow is kept.
* `tags` - (Optional) Tags of the policy.
* `scheduled` - (Optional) Whether the policy is scheduled. When not set, the value chosen by IdentityNow is kept. Use `identitynow_sod_policy_schedule` to manage the schedule itself.
* `violation_owner_assignment_config` - (Optional) Who owns the violations of the policy. At most one block. When the block is not configured, the setting is not managed: the value in IdentityNow is kept and not tracked. Contains:
  * `assignment_rule` - (Optional) `MANAGER` (the manager of the identity in violation) or `STATIC` (the identity or governance group in `owner_ref`).
  * `owner_ref` - (Optional) Owner of the violations for the `STATIC` rule. At most one block. Contains `id` (Required), `type` (Required, `IDENTITY`, `GOVERNANCE_GROUP` or `MANAGER`) and `name` (Optional). For the `MANAGER` rule, leave it out: a reference without ID that the API returns for the rule (`type = MANAGER`) is not shown when the block is not configured.

JSON arguments are compared with the API value on the configured fields only: formatting, key order and fields IdentityNow adds, such as entitlement names, do not produce a diff.

## Attributes Reference

In addition to the arguments listed above, the following attributes are exported:

* `id` - SOD policy ID.
* `policy_query` - Search query of the policy, generated for `CONFLICTING_ACCESS_BASED` policies.
* `creator_id` - ID of the identity that created the policy.
* `modifier_id` - ID of the identity that last modified the policy.
* `created` - Creation date.
* `modified` - Last modification date.

## Update Behaviour

`GENERAL` policies are updated with PUT: the current policy is read, the configured fields are replaced and the policy is written back, so fields that are not managed are kept. `CONFLICTING_ACCESS_BASED` policies are updated with a JSON Patch of the changed fields, because their query cannot be written. Destroying the resource permanently deletes the policy (`logical=false`) instead of the soft delete that is the API default.

## Import

SOD policies can be imported using their ID:

```shell
terraform import identitynow_sod_policy.example <sod-policy-id>
```
