# identitynow_multihost

Manages a Multi-Host Integration, which holds sources of the same type, e.g. many Microsoft SQL Server databases. A token with the Org Admin or Multi-Host Admin authority is required. Uploading connector files and creating the sources of the integration are not supported by this resource.

Updates use JSON Patch. The API only supports adding and replacing values, so:

* removing the `cluster` or `management_workgroup` block sends a replace with a null value,
* connector attributes removed from `connector_attributes_json` are left unchanged in IdentityNow (the provider shows a warning), also inside nested objects,
* only changed connector attributes are sent; inside a nested object that already exists in IdentityNow, such as `multiHostAttributes`, only the changed values are sent, so values that are not configured (e.g. `connector_files`) are kept,
* `max_sources_per_agg_group` and `max_allowed_sources` are only managed while they are set.

## Example Usage

```terraform
variable "sql_server_password" {
  type      = string
  sensitive = true
}

resource "identitynow_multihost" "sql_servers" {
  name        = "SQL Servers"
  description = "Microsoft SQL Server databases"
  connector   = "multihost-microsoft-sql-server"
  connector_attributes_json = jsonencode({
    multiHostAttributes = {
      authType = "SQLAuthentication"
      user     = "svc_identitynow"
      password = var.sql_server_password
    }
  })
  max_sources_per_agg_group = 10
  max_allowed_sources       = 300

  owner {
    id = "2c9180a46faadee4016fb4e018c20639"
  }

  cluster {
    id = "2c9180887de347b4017de8859bf35d3e"
  }
}
```

## Schema

### Required

- `connector` (String) Connector script name, e.g. `multihost-microsoft-sql-server`. Changing this forces a new Multi-Host Integration to be created, which also deletes its sources.
- `description` (String) Description of the Multi-Host Integration.
- `name` (String) Name of the Multi-Host Integration.

### Optional

- `cluster` (Block List) Virtual appliance cluster of the Multi-Host Integration. At most one block. (see [below for nested schema](#nestedblock--cluster))
- `connector_attributes_json` (String, Sensitive) Connector attributes as a JSON object, e.g. `multiHostAttributes` with `authType`, `user` and `password`. Use `jsonencode()` for convenience. This value is sensitive, since it may contain credentials. Only the configured keys are managed and compared, also inside nested objects such as `multiHostAttributes`: attributes added by IdentityNow are ignored, and configured values that the API does not return, or returns masked or encrypted, keep the configured value. Updates only send the changed values, so attributes of a nested object that are not configured are kept. Keys removed from the configuration are left unchanged in IdentityNow, since the API cannot remove attributes. Use `max_sources_per_agg_group` and `max_allowed_sources` instead of the `maxSourcesPerAggGroup` and `maxAllowedSources` keys. After import the value is null until it is configured.
- `management_workgroup` (Block List) Governance group that manages the Multi-Host Integration. At most one block. (see [below for nested schema](#nestedblock--management_workgroup))
- `max_allowed_sources` (Number) Maximum number of sources in the Multi-Host Integration (connector attribute `maxAllowedSources`). When not set, the value is not managed.
- `max_sources_per_agg_group` (Number) Maximum number of sources per aggregation group (connector attribute `maxSourcesPerAggGroup`). When not set, the value is not managed.
- `owner` (Block List) Identity that owns the Multi-Host Integration. Exactly one block is required. (see [below for nested schema](#nestedblock--owner))

### Read-Only

- `created` (String) Creation date.
- `id` (String) Multi-Host Integration ID.
- `modified` (String) Last modification date.
- `type` (String) Type of system managed, e.g. `Multi-Host - Microsoft SQL Server`.
