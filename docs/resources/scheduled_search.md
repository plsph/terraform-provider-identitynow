# identitynow_scheduled_search

Manages a scheduled search, which runs a saved search on a schedule and emails the results to its recipients. The scheduled search is owned by the identity the provider authenticates as.

## Example Usage

```terraform
resource "identitynow_saved_search" "disabled_accounts" {
  name    = "Identities with disabled accounts"
  indices = ["identities"]
  query   = "@accounts(disabled:true)"
}

resource "identitynow_scheduled_search" "disabled_accounts_daily" {
  name                  = "Daily disabled accounts report"
  saved_search_id       = identitynow_saved_search.disabled_accounts.id
  enabled               = true
  email_empty_results   = false
  display_query_details = false

  schedule_json = jsonencode({
    type       = "DAILY"
    hours      = { type = "LIST", values = ["9"] }
    timeZoneId = "Europe/Warsaw"
  })

  recipient {
    id = "2c91808568c529c60168cca6f90c1313"
  }
}
```

## Schema

### Required

- `saved_search_id` (String) ID of the saved search that is run.
- `schedule_json` (String) Schedule as a JSON object with `type` (`DAILY`, `WEEKLY`, `MONTHLY`, `CALENDAR` or `ANNUALLY`), the `months`, `days` and `hours` selectors (each with `type` `LIST` or `RANGE`, `values` and an optional `interval`), `expiration` and `timeZoneId`. `hours` is required. Use `jsonencode()`. The value is compared on the configured fields only, so formatting, key order and fields IdentityNow adds do not produce a diff.

### Optional

- `description` (String) Scheduled search description.
- `display_query_details` (Boolean) Whether the email includes the query and a preview of the results, which can contain personal data. When not set, the value chosen by IdentityNow is kept.
- `email_empty_results` (Boolean) Whether an email is sent when the search returns no results. When not set, the value chosen by IdentityNow is kept.
- `enabled` (Boolean) Whether the scheduled search is enabled. When not set, the value chosen by IdentityNow is kept.
- `name` (String) Scheduled search name.
- `recipient` (Block List) Identity that receives the search results by email. At least one block is required. (see [below for nested schema](#nestedblock--recipient))

### Read-Only

- `created` (String) Creation date.
- `id` (String) Scheduled search ID.
- `modified` (String) Last modification date.
- `owner` (Attributes List) Owner of the scheduled search, with `type` and `id`. Set by the API to the identity that created it. (see [below for nested schema](#nestedatt--owner))

## Update Behaviour

Updates use PUT: the current scheduled search is read, the configured fields are replaced and the scheduled search is written back, so the owner is kept.

## Import

Scheduled searches can be imported using their ID:

```shell
terraform import identitynow_scheduled_search.example <scheduled-search-id>
```
