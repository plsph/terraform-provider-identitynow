# identitynow_sdi_status_check_config

Manages how often and how long the status of queued service desk integration (SDI) tickets is checked.

There is one status check configuration per tenant, it cannot be created or deleted. Creating the resource applies the configured settings to the existing status check configuration, and destroying it only removes it from Terraform state: the settings are left unchanged in IdentityNow.

Only the settings present in the configuration are managed. Settings that are not configured are never changed or reset; they show the current tenant value. Removing a setting from the configuration stops managing it and leaves its current value in place. The API replaces the whole status check configuration on update, so the provider reads the current status check configuration, replaces the configured settings and sends it back.

## Example Usage

```terraform
resource "identitynow_sdi_status_check_config" "this" {
  provisioning_status_check_interval_minutes = 30
  provisioning_max_status_check_days         = 2
}
```

All arguments are optional; settings that are not configured keep their current value.

## Schema

### Optional

- `provisioning_max_status_check_days` (Number) Maximum number of days the status is checked. When not configured, the current tenant value is kept and shown.
- `provisioning_status_check_interval_minutes` (Number) Interval in minutes between status checks. When not configured, the current tenant value is kept and shown.

### Read-Only

- `id` (String) Always `sdi-status-check-config`.

## Import

The settings can be imported with any ID; the ID is always set to `sdi-status-check-config`:

```shell
terraform import identitynow_sdi_status_check_config.this sdi-status-check-config
```
