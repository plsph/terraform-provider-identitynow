# identitynow_mfa_okta_config

Manages the tenant-wide Okta Verify multi-factor authentication configuration.

There is one Okta Verify configuration per tenant, it cannot be created or deleted. Creating the resource applies the configured settings to the existing Okta Verify configuration, and destroying it only removes it from Terraform state: the settings are left unchanged in IdentityNow.

Only the settings present in the configuration are managed. Settings that are not configured are never changed or reset; they show the current tenant value. Removing a setting from the configuration stops managing it and leaves its current value in place. The API replaces the whole Okta Verify configuration on update, so the provider reads the current Okta Verify configuration, replaces the configured settings and sends it back.

`access_key` is sensitive. When the API does not return it, the known value is kept in state. Settings that are not configured are sent back with the value returned by the API.

Because the update sends the whole configuration, an access key that the API does not return cannot be sent back. In that case the update fails with an error asking you to configure `access_key` instead of clearing it. This matters after an import, or when only some settings such as `enabled` are configured.

## Example Usage

```terraform
variable "okta_api_token" {
  description = "Okta API token."
  type        = string
  sensitive   = true
}

resource "identitynow_mfa_okta_config" "this" {
  enabled            = true
  host               = "example.okta.com"
  identity_attribute = "email"
  access_key         = var.okta_api_token
}
```

All arguments are optional; settings that are not configured keep their current value.

## Schema

### Optional

- `access_key` (String, Sensitive) Okta API token. The value is sensitive. When the API does not return the value, the known value is kept in state, and it must be configured, because the update would clear it. When not configured, the current tenant value is kept and shown.
- `enabled` (Boolean) Whether the MFA method is enabled. When not configured, the current tenant value is kept and shown.
- `host` (String) Host name of the Okta organization, e.g. `example.okta.com`. When not configured, the current tenant value is kept and shown.
- `identity_attribute` (String) Identity attribute that maps identities to Okta users, e.g. `email`. When not configured, the current tenant value is kept and shown.

### Read-Only

- `id` (String) Always `mfa-okta-config`.
- `mfa_method` (String) MFA method name (`okta-verify`).

## Import

The settings can be imported with any ID; the ID is always set to `mfa-okta-config`:

```shell
terraform import identitynow_mfa_okta_config.this mfa-okta-config
```
