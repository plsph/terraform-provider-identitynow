# identitynow_sod_policy_schedule

Manages the schedule on which the violation report of a separation of duties (SOD) policy is run and emailed to its recipients. A policy has at most one schedule, so the schedule is identified by the policy ID. Every create and update replaces the whole schedule.

## Example Usage

```terraform
resource "identitynow_sod_policy_schedule" "weekly" {
  policy_id           = "0f11f2a4-7c94-4bf3-a2bd-742580fe3bde"
  name                = "Weekly SOD report"
  description         = "Sent every Monday at 8 AM"
  email_empty_results = false

  schedule_json = jsonencode({
    type       = "WEEKLY"
    days       = { type = "LIST", values = ["MON"] }
    hours      = { type = "LIST", values = ["8"] }
    timeZoneId = "Europe/Warsaw"
  })

  recipient {
    id = "2c91808568c529c60168cca6f90c1313"
  }
}
```

## Schema

### Required

- `policy_id` (String) ID of the scheduled SOD policy. Changing this forces a new schedule to be created.
- `schedule_json` (String) Schedule as a JSON object with `type` (`DAILY`, `WEEKLY`, `MONTHLY`, `CALENDAR` or `ANNUALLY`), the `months`, `days` and `hours` selectors (each with `type` `LIST` or `RANGE`, `values` and an optional `interval`), `expiration` and `timeZoneId`. `hours` is required. Use `jsonencode()`. The value is compared on the configured fields only, so formatting, key order and fields IdentityNow adds do not produce a diff.

### Optional

- `description` (String) Schedule description.
- `email_empty_results` (Boolean) Whether the report is emailed when it has no results. When not set, the value chosen by IdentityNow is kept.
- `name` (String) Schedule name.
- `recipient` (Block List) Identity that receives the violation report. (see [below for nested schema](#nestedblock--recipient))

### Read-Only

- `created` (String) Creation date.
- `creator_id` (String) ID of the identity that created the schedule.
- `id` (String) SOD policy ID, the schedule has no ID of its own.
- `modified` (String) Last modification date.
- `modifier_id` (String) ID of the identity that last modified the schedule.

## Import

SOD policy schedules can be imported using the SOD policy ID:

```shell
terraform import identitynow_sod_policy_schedule.example <sod-policy-id>
```
