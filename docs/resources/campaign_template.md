# identitynow_campaign_template

Manages a certification campaign template. Campaigns can be generated from the template manually or on a schedule managed with `identitynow_campaign_template_schedule`. The template is owned by the identity the provider authenticates as.

## Example Usage

```hcl
resource "identitynow_campaign_template" "quarterly_managers" {
  name              = "Quarterly manager certification"
  description       = "Managers review the access of their reports every quarter."
  deadline_duration = "P2W"

  campaign_json = jsonencode({
    name                     = "Manager certification %TIME_PERIOD%"
    description              = "Review the access of your reports"
    type                     = "MANAGER"
    emailNotificationEnabled = true
    autoRevokeAllowed        = false
    recommendationsEnabled   = true
  })
}
```

## Arguments Reference

The following arguments are supported:

* `name` - (Required) Template name. It has no bearing on the names of generated campaigns.
* `description` - (Required) Template description. It has no bearing on the descriptions of generated campaigns.
* `campaign_json` - (Required) Definition of the campaigns generated from the template as a JSON object: `name`, `description`, `type` (`MANAGER`, `SOURCE_OWNER`, `SEARCH`, `ROLE_COMPOSITION` or `MACHINE_ACCOUNT`), flags such as `emailNotificationEnabled`, `autoRevokeAllowed`, `recommendationsEnabled` and `sunsetCommentsRequired`, `mandatoryCommentRequirement`, `filter`, `correlatedStatus` and the type specific `searchCampaignInfo`, `sourceOwnerCampaignInfo`, `roleCompositionCampaignInfo` or `machineAccountCampaignInfo`. Campaign names and descriptions can use the placeholders documented for the campaign template generate API. Use `jsonencode()`.
* `deadline_duration` - (Optional) Time period in which generated campaigns must be completed, as an ISO-8601 duration such as `P2W`. The deadline of a generated campaign is the generation date plus this duration.

`campaign_json` is compared with the API value on the configured fields only: formatting, key order, defaults and read-only fields IdentityNow adds (`id`, `status`, `created`, `alerts` and similar) do not produce a diff. Read-only fields are not stored in state.

## Attributes Reference

In addition to the arguments listed above, the following attributes are exported:

* `id` - Campaign template ID.
* `scheduled` - Whether the template has a schedule.
* `owner_ref` - Owner of the template and of the campaigns generated by its schedule, with `id`, `type` and `name`.
* `created` - Creation date.
* `modified` - Last modification date.

## Update Behaviour

Updates send a JSON Patch with the changed fields only. A change of `campaign_json` replaces the whole campaign definition.

## Import

Campaign templates can be imported using their ID:

```shell
terraform import identitynow_campaign_template.example <campaign-template-id>
```
